# 时钟频偏计算

## 基本概念

- **PPM**（Parts Per Million，百万分之一）：表示时钟偏差占标称频率的比例，1 PPM = 10⁻⁶
- **PPB**（Parts Per Billion，十亿分之一）：表示时钟偏差占标称频率的比例，1 PPB = 10⁻⁹
- 换算关系：**1 PPM = 1000 PPB**

PPM/PPB 描述的是**相对偏差**，与具体频率无关，适用于任何时钟源（晶振、原子钟等）。

## 计算公式

### 由实测频率计算偏差

```text
偏差(Hz) = 实测频率 - 标称频率

PPM = (偏差 / 标称频率) × 10⁶
PPB = (偏差 / 标称频率) × 10⁹
```

### 由 PPM/PPB 反算频率偏差

```text
偏差(Hz) = 标称频率 × PPM × 10⁻⁶
偏差(Hz) = 标称频率 × PPB × 10⁻⁹
```

### 由 PPM 换算时间偏差

```text
每天偏差(秒) = 86400 × PPM × 10⁻⁶ = PPM × 0.0864
```

| PPM | 每天偏差 | 每年偏差 |
| ---- | -------- | -------- |
| 0.01 | 0.864 秒 | ~5.26 分钟 |
| 0.1 | 8.64 秒 | ~52.6 分钟 |
| 1 | 86.4 秒 | ~8.78 小时 |
| 10 | 864 秒（14.4 分钟） | ~3.65 天 |
| 100 | 8640 秒（2.4 小时） | ~36.5 天 |

## 计算示例

### 示例1：PTP 时钟频偏

一颗 25MHz 晶振，实测输出 25,000,025 Hz：

```text
偏差 = 25,000,025 - 25,000,000 = 25 Hz
PPM  = (25 / 25,000,000) × 10⁶ = 1 PPM
PPB  = 1000 PPB
```

该晶振每天会产生约 86.4 秒的时间偏差。

### 示例2：Linux PHC 频偏调整

Linux `phc2sys` 输出 `phc_offset: -1234 ns, freq: -15 ppb`，表示：

- 时钟偏慢，需将 PHC 频率上调 15 PPB
- 对于 1GHz 时钟，对应频率调整量：`1,000,000,000 × 15 × 10⁻⁹ = 15 Hz`

### 示例3：晶振精度等级

| 精度等级 | 典型 PPM | 典型应用 |
| -------- | -------- | -------- |
| 普通晶振（XO） | ±20 ~ ±100 | 消费电子 |
| 温补晶振（TCXO） | ±0.5 ~ ±2 | GPS、通信 |
| 恒温晶振（OCXO） | ±0.001 ~ ±0.01 | 基站、仪器 |
| 铷原子钟 | ±0.0001 | 时间服务器 |
| 铯原子钟 | ±0.000001 | 国家授时 |

## PTP/PTP 中的频偏校正

在 IEEE 1588 (PTP) 协议中，从时钟通过以下方式校正频偏：

1. **测量**：通过 Sync/Delay_Resp 报文时间戳计算主从时钟偏差
2. **计算频偏**：连续两次偏差的变化率即为频偏
3. **调整本地时钟频率**：通过 `clock_adjtime()` 系统调用调整 PHC 频率

```bash
# 查看 PHC 时钟频偏
pmc -u -b 0 'GET CURRENT_DATA_SET'

# phc2sys 同步并查看频偏
phc2sys -s eth0 -c CLOCK_REALTIME -w -m
```
