# MIPI CSI-2 接口基础知识

## 1. MIPI Alliance 简介

**MIPI Alliance**（移动产业处理器接口联盟）成立于 2003 年，由 ARM、Nokia、ST、TI 等公司发起，目前有 265+ 家成员企业。它制定了一套覆盖移动/嵌入式设备内部互联的接口规范，涵盖物理层、多媒体、芯片间通信、音频、射频控制、调试等六大类。

在嵌入式开发中最常接触的是：

| 类别 | 规范 | 典型用途 |
| ------ | ------ | ------ |
| 物理层 | D-PHY、C-PHY、M-PHY | 高速串行链路的电气标准 |
| 多媒体 | CSI-2（摄像头）、DSI-2（显示屏） | 图像传感器和显示面板接口 |
| 传感器 | I3C / I3C Basic | IMU、环境传感器等低速外设 |

## 2. MIPI CSI-2 协议层

**CSI-2**（Camera Serial Interface 2）是 MIPI 定义的高速摄像头接口协议，运行在 D-PHY 或 C-PHY 之上。几乎所有嵌入式 SoC 的 Camera 接口都基于 CSI-2。

### 2.1 协议分层

```text
┌──────────────────────────┐
│      Application Layer   │  应用层：系统级帧控制
├──────────────────────────┤
│  Pixel-to-Byte Pack Layer│  像素打包层：像素→字节流
├──────────────────────────┤
│  Low Level Protocol Layer│  LLP层：数据包封装（头+载荷+尾）
├──────────────────────────┤
│   Lane Management Layer  │  通道管理层：多 Lane 分发/重组
├──────────────────────────┤
│        PHY Layer         │  物理层：D-PHY 或 C-PHY
└──────────────────────────┘
```

### 2.2 数据类型

CSI-2 通过 Data Identifier（DI）字节标识数据类型，DI 的低 6 位为数据类型，高 2 位为虚拟通道号。

| 数据类型编码 | 类别 | 示例 |
| ------ | ------ | ------ |
| `0x00`-`0x07` | 同步短包 | FS（帧起始）、FE（帧结束）、LS、LE |
| `0x18`-`0x1F` | YUV | YUV422 8-bit、YUV420 8-bit |
| `0x20`-`0x27` | RGB | RGB565、RGB888 |
| `0x28`-`0x2F` | RAW | RAW8、RAW10、RAW12 |
| `0x30`-`0x37` | JPEG / 自定义 | JPEG 压缩数据 |

> 一个长包（Long Packet）承载**一整行**图像数据。

### 2.3 虚拟通道

虚拟通道允许在**同一条物理链路**上复用多个独立数据流：

- CSI-2 v1.x：支持 **4 个虚拟通道**（VC 0-3）
- CSI-2 v2.x：扩展到 **32 个虚拟通道**

典型应用：多摄合一路 CSI、多曝光 HDR Sensor（不同曝光帧走不同 VC）。

### 2.4 数据包结构

**短包**（4 字节，无载荷）— 用于帧/行同步：

```text
┌────────┬──────────────────┬───────┐
│ DI(8b) │  WC/Command(16b) │ECC(8b)│
└────────┴──────────────────┴───────┘
  VC+DT      帧计数/行计数      校验
```

**长包**（32b 头部 + 变长载荷 + 16b 尾部）— 承载像素数据：

```text
┌────────┬──────────┬───────┬─────────────┬─────────┐
│ DI(8b) │  WC(16b) │ECC(8b)│   Payload   │ CRC(16b)│
└────────┴──────────┴───────┴─────────────┴─────────┘
│◄── Packet Header(32b) ──►│◄── N 字节 ──►│◄ Footer ►│
```

- **WC**：载荷字节数（最大 65535）
- **ECC**：汉明码，可纠正 1 bit 错误、检测 2 bit 错误
- **CRC**：对整个载荷做 16-bit CRC 校验

一帧数据的完整传输序列：

```text
FS(短包) → Line0(长包) → Line1(长包) → ... → LineN(长包) → FE(短包)
```

## 3. D-PHY

D-PHY 是 MIPI 最早定义的物理层，也是目前使用最广泛的摄像头/显示 PHY。

### 3.1 Lane 结构

- **1 条专用时钟 Lane**（差分对：CLKp / CLKn）
- **1-4 条数据 Lane**（每条是差分对：Dp / Dn）
- 所有 Lane 都是**点对点、单向**的（TX → RX）
- 引脚数：2（时钟）+ 2×N（数据）。4 Lane 配置 = **10 引脚**

```text
         TX (Sensor)                              RX (SoC)
        ┌──────────┐                            ┌──────────┐
        │     CLKp ├─────────── CLKp ───────────┤ CLKp     │
        │     CLKn ├─────────── CLKn ───────────┤ CLKn     │
        │      D0p ├─────────── D0p ────────────┤ D0p      │
        │      D0n ├─────────── D0n ────────────┤ D0n      │
        │      D1p ├─────────── D1p ────────────┤ D1p      │
        │      D1n ├─────────── D1n ────────────┤ D1n      │
        │      ...  │                            │  ...     │
        └──────────┘                            └──────────┘
```

### 3.2 双模式信号

D-PHY 有两种电气模式：

| 模式 | 类型 | 电压摆幅 | 速率 | 用途 |
| ------ | ------ | ------ | ------ | ------ |
| **LP**（低功耗） | 单端，无端接 | 0 ~ 1.2 V（每根线） | ~10 Mbps | 控制命令、空闲态 |
| **HS**（高速） | 差分，100Ω 端接 | 200 mV（差分） | 最高 4.5 Gbps/lane | 图像数据传输 |

HS 模式的共模电压仅 150-250 mV，非常省电。

### 3.3 Lane 状态

| 状态 | Dp | Dn | 模式 | 含义 |
| ------ | ------ | ------ | ------ | ------ |
| LP-11 | High | High | LP | 空闲/停止态（默认） |
| LP-01 | Low | High | LP | 控制/转向 |
| LP-10 | High | Low | LP | 控制/转向 |
| LP-00 | Low | Low | LP | 停止态 |
| HS-0 | Dn > Dp | — | HS | 差分低 |
| HS-1 | Dp > Dn | — | HS | 差分高 |

从 LP 进入 HS 的典型序列：`LP-11 → LP-01 → LP-00 → HS-0（SoT 起始）`。

### 3.4 编码方式

HS 数据使用 **NRZ**（不归零）编码。时钟 Lane 在 HS 模式下以比特率翻转，提供 **DDR 时钟**（双边沿有效）。数据在时钟的上升沿和下降沿都被采样。

### 3.5 各版本数据率

| 版本 | 每条 Lane 最大速率 | 发布年份 |
| ------ | ------ | ------ |
| v1.0 | 1.0 Gbps | 2009 |
| v1.1 | 1.5 Gbps | 2011 |
| v1.2 | 2.5 Gbps | 2014 |
| v2.0/v2.1 | 4.5 Gbps | 2017+ |

> 4 Lane D-PHY v1.2 总带宽 = 4 × 2.5 = **10 Gbps**。

## 4. C-PHY

C-PHY 是 MIPI 定义的新一代物理层，目标是在更少的信号线上提供更高的带宽。

### 4.1 三相符号编码

C-PHY 与 D-PHY 的核心区别：

- 每条 Lane（称为 **Trio**）由 **3 根线**（A、B、C）组成，而非差分对
- 每根线上是 **3 电平** 单端信号（低、中、高）
- 通过 **状态转移**（而非绝对电平）传递数据
- 每次只有一个 Wire 改变状态，从任意状态出发有 **6 种可能的转移**

```text
         TX (Sensor)                           RX (SoC)
        ┌──────────┐                         ┌──────────┐
        │     Tri0 │                         │ Tri0     │
        │     WireA ├──── A0 ────────────────┤ WireA    │
        │     WireB ├──── B0 ────────────────┤ WireB    │
        │     WireC ├──── C0 ────────────────┤ WireC    │
        │          │                         │          │
        │     Tri1 │                         │ Tri1     │
        │     WireA ├──── A1 ────────────────┤ WireA    │
        │     WireB ├──── B1 ────────────────┤ WireB    │
        │     WireC ├──── C1 ────────────────┤ WireC    │
        └──────────┘                         └──────────┘
    （无专用时钟 Lane）
```

### 4.2 嵌入式时钟

C-PHY **没有专用时钟 Lane**。时钟嵌入在数据流中：

- 每次 Trio 上的相位转移都产生一个时钟沿
- 接收端通过 **CDR（时钟数据恢复）** 电路从三相转移中提取时钟
- 接收端监测三组差分对组合（A-B、B-C、C-A）来恢复时钟脉冲

### 4.3 编码效率

6 状态转移模式下，每个符号编码 **16/7 ≈ 2.28 bit**。

| 版本 | 每 Trio 符号率 | 有效数据率 | 编码方式 |
| ------ | ------ | ------ | ------ |
| v1.0 | 2.5 Gsps | ~5.7 Gbps | 6-wirestate |
| v1.1 | 3.5 Gsps | ~8.0 Gbps | 6-wirestate |
| v2.0 | 4.5 Gsps | ~10.3 Gbps | 6-wirestate |

> 对比：C-PHY v1.0 一个 Trio 的有效带宽 ≈ D-PHY v1.2 两条 Lane 的带宽。

### 4.4 D-PHY vs C-PHY 对比

| 参数 | D-PHY | C-PHY |
| ------ | ------ | ------ |
| **每 Lane 线数** | 2（差分对） | 3（Trio） |
| **时钟 Lane** | 必须有专用时钟 Lane | 无，时钟嵌入数据 |
| **信号方式** | 差分 2 电平（NRZ） | 3 相 3 电平单端 |
| **v1.x 最大速率** | 2.5 Gbps/Lane | 5.7 Gbps/Trio |
| **4 Lane 引脚数** | 10（2 clk + 8 data） | 12（4×3，无 clk） |
| **每引脚对带宽** | ~1.25 Gbps/pin | ~1.9 Gbps/pin |
| **功耗** | 低 | 略高 |
| **兼容性** | 最广泛，主流 Sensor 都支持 | 新一代高分辨率 Sensor 选用 |

总结：C-PHY 每线对带宽约为 D-PHY 的 **2 倍**，但编解码逻辑更复杂，需要 3 根线而非 2 根。

## 5. D/C-PHY Combo（组合 PHY）

现代 SoC 通常需要同时兼容 D-PHY Sensor（量大、成本低）和 C-PHY Sensor（高分辨率）。为节省引脚和芯片面积，很多 SoC 集成了 **D-PHY / C-PHY 组合 PHY**。

### 5.1 引脚复用原理

- C-PHY 的 Trio（3 线）和 D-PHY 的差分对（其中 2 线）**共享同一组物理引脚**
- C-PHY 使用全部 3 根线，D-PHY 使用其中 2 根作为差分对
- 通过寄存器配置选择当前工作模式（D-PHY 或 C-PHY）

```text
         引脚复用示意
        ┌────────────────────────┐
        │  SoC Pad Group (3 pin) │
        │                        │
        │   Pin A ◄─────────────┤─── C-PHY: Wire A
        │   Pin B ◄─────────────┤─── C-PHY: Wire B  ┐
        │   Pin C ◄─────────────┤─── C-PHY: Wire C  │ D-PHY: Dp/Dn 差分对
        │                        │                   │ （用其中两根）
        └────────────────────────┘
```

### 5.2 工作模式

- 同一时刻，一个 Lane/Trio 只能工作在 **D-PHY 或 C-PHY 其中一种模式**
- 通过 SoC 的 CSI 控制器寄存器在初始化时选择 PHY 类型
- 部分 SoC 支持不同 Lane 组运行不同模式（例如 Lane 0-1 跑 D-PHY，Lane 2-3 跑 C-PHY）

### 5.3 实际配置示例

一个有 4 组数据引脚（+ 1 组时钟引脚）的 SoC Camera 接口：

| 模式 | 引脚使用 | 总带宽（v1.x） |
| ------ | ------ | ------ |
| D-PHY 4 Lane | 10 pin（2 clk + 8 data） | 4 × 2.5 = 10 Gbps |
| C-PHY 3 Trio | 9 pin（3×3，无需 clk） | 3 × 5.7 = 17.1 Gbps |
| C-PHY 4 Trio | 12 pin（4×3） | 4 × 5.7 = 22.8 Gbps |

### 5.4 支持 Combo PHY 的平台

| 平台/厂商 | 说明 |
| ------ | ------ |
| **RK3588** | 4 个 MIPI CSI，部分接口支持 D-PHY/C-PHY 可配置 |
| **RK3576** | MIPI CSI 支持 D-PHY 和 C-PHY 模式切换 |
| **NXP i.MX 8** | D-PHY I/O 引脚同时支持 C-PHY |
| **NVIDIA Jetson** | 可配置 MIPI CSI 支持 D-PHY 和 C-PHY |
| **Mixel IP** | 提供双模 D-PHY/C-PHY combo PHY IP，共享模拟/数字模块 |

## 6. 选型建议

| 场景 | 推荐方案 |
| ------ | ------ |
| 普通 1080p/4K 摄像头 | D-PHY 2-4 Lane，兼容性最好 |
| 高分辨率（48MP+）或高帧率 | C-PHY，带宽优势明显 |
| 多摄汇聚（4 摄合一 CSI） | C-PHY + Virtual Channel |
| 新设计 + 兼容旧 Sensor | D/C-PHY Combo，灵活切换 |
| 低成本方案 | D-PHY 1-2 Lane，Sensor 选项最多 |
