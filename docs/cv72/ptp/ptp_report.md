# 音视频 PTP 高精度同步


## 1. 视频方案

### 核心改造

废除依赖 Linux 内核调度的软件 `hrtimer` 生成 VSYNC 的方式，改为纯硬件链路：由以太网 MAC 层直接输出 30Hz 的 PPS（秒脉冲）信号，在物理层（PCB 走线）直接作为 VSYNC 输入给 Sensor。

### 性能对比与提升

- **旧方案（hrtimer）精度**：受限于操作系统调度抖动、中断响应延迟，触发精度通常 **±100μs 级别** 波动
- **新方案（MAC PPS）精度**：纯硬件纳秒级触发，规避了软件抖动，触发精度可达 **亚微秒级（< 1μs）** 甚至纳秒级

### 烤机一晚上数据

**核心提升：**

1. 实现多台设备 Sensor 曝光的**绝对物理级"同启同停"**（Genlock 级别同步）
2. 彻底消除了因为系统 CPU 负载波动导致的帧率不稳问题
3. 结合 PTP 协议，实现了基于网络绝对时间的视频相位对齐与频率锁定

**现有缺陷：**

1. 不同 sensor 收到 vsync 信号后曝光和出帧的时间有差异。
2. 同 DPHY 和 CPHY 出帧时间也有点差异。

## 2. 音频方案

### 理论基础：物理同源与误差等效

- **时钟绑定**：网络硬件时钟（PHC）与音频时钟（Audio PLL）由同一颗 24MHz 物理晶振驱动。物理晶振的频率漂移，会以**绝对相同的比例**同时映射到网络与音频系统上
- **误差等效**：PTP 协议计算出的纠偏值（`freq`，单位 PPB）是一个无量纲的相对比例。因此，直接提取 PHC 域的 PPB 变量，跨域注入到音频时钟域，即可实现等效纠偏

### 系统同步链路

1. **提取**：`ptp4l` 伺服环路计算出补偿本地晶振的稳态频偏（PPB）
2. **滤波**：软件中间件对其进行 EMA 滤波，隔离网络延时抖动（Jitter），提取平滑的漂移趋势值
3. **注入**：将平滑后的 PPB 值转化为控制参数，直接写入 SoC 的 Audio PLL 寄存器
4. **限幅**：限制改动范围，规避大的网络波动导致 `audio_clk` 震荡
5. **锁定**：音频播放频率实时动态追平远端 PTP 主时钟

### 烤机一晚上

#### 当前落地现状与成果

- **旧方案**：依赖 ALSA 采集、DMA 产生 1秒 PPS，再由软件去计算与 PHC 时钟的偏差，进而去调整 Audio PLL。链路长、延迟高、误差累积大。收系统调度影响大，高负载情况下，alsa 采集，DMA 中断产生的 pps 误差可以达到 **±40~100μs** 的误差，进而导致后面算法计算出 audio_clk 误差
- **新方案**：直取 PTP 核心数据，在 PTP 网络稳定情况下，多台从机设备 MCLK 的相互偏差被成功限制在 **1~2Hz 以内**

#### 数学换算

以 12.288MHz 音频主频为例：

> 1Hz 的频率偏差 ≈ **81.38 PPB**（即 1 / 12,288,000 的相对误差）

#### 现有缺陷

1. **缺乏高精度小数微调**：Audio PLL 不支持 PPB 级别的精细小数写入，只能以 1Hz（约 81.38 PPB）为步长进行粗略的台阶式跳变（量化误差）
2. **寄存器生效异常（硬件 Bug）**：写入个别特定频率值时硬件不生效，导致频率调整曲线出现断层
