# 安霸 CV72 开发心得

CV72 的媒体 Pipeline 主要通过 `.lua` 配置文件 + `test_encode` 工具来搭建。

## 1. test_encode 核心参数分类与解析

### 流与通道管理

- `-S/--stream [0~19]`：指定要操作的编码流（Stream）ID。主码流通常是 0，子码流是 1、2 等
- `-c/--chan [0~4]`：指定视频输入通道（Channel）ID。一个通道可以供给多个编码流

### 编码格式与分辨率设定

- `-h/--h264 [分辨率]`：H.264 编码，指定分辨率（如 1080p）
- `-H/--h265 [分辨率]`：H.265 编码
- `-m/--mjpeg [分辨率]`：MJPEG 编码
- `-n/--none`：编码类型设为 NONE，通常用于仅预览不编码

### 码率控制与图像质量

- `--bc [cbr|vbr|...]`：指定码率控制模式
- `--bitrate [value]`：CBR 平均码率（单位：bps）
- `--vbr-bitrate [min~max]`：VBR 码率范围
- `-q/--quality [质量]`：JPEG/MJPEG 编码质量（1-100）

### GOP 结构与高级编码控制

- `-M, -N, --idr`：设置 GOP 结构（M 为 IP 帧间隔，N 为 GOP 长度，IDR 帧间隔）
- `--gop [0~8]`：选择 GOP 模型（如 SVCT 分层编码、快速定位 GOP 等）
- `--force-idr`：强制插入一个 IDR 帧
- `--hflip/--vflip`：水平/垂直翻转

### 系统配置与资源管理

- **`--resource-cfg <文件>`**：最关键参数之一，指定定义整个视频输入管线（VIN/ISP/通道/画布）的 Lua 配置文件
- **`--vout-cfg <文件>`**：指定视频输出（显示）的 Lua 配置文件
- `--max-stream-num [2~20]`：指定当前模式下支持的最大编码流数量

### 信息查询与调试

```bash
--show-system-state          Show system state
--show-encode-config         Show stream(H.264/H.265/MJPEG) encode config
--show-stream-info           Show stream format, size, info & state
--show-resource-info         Show codec resource limit info
--show-enc-mode-cap          Show encode mode capability
--show-driver-info           Show IAV driver info
--show-chip-info             Show chip info
--show-dram-layout           Show DRAM layout info
--show-feature-set           Show feature set info
--show-resource-cfg          Show resource config
--show-canvas-state          Show canvas state
--show-vsrc-info             Show vsrc information including sensor name, topology
--show-vout-info             Show vout information
--show-all-info              Show all info
```

### 操作控制

- `-e/--encode`：开始编码
- `-s/--stop`：停止编码
- `--start-multi [m~n]`：启动多个流（如 `--start-multi 0~2` 启动流 0、1、2）
- `--nopreview`：不进入预览模式，直接编码（常用于后台服务）

## 2. test_encode 典型工作流与命令示例

### 场景1：基础单流编码测试

```bash
# 配置流0为H.265 1080p，使用指定的资源配置文件，并开始编码
test_encode -S 0 -H 1080p --resource-cfg /etc/amba/lua/imx327_4m.lua -e
```

### 场景2：配置多路编码并查询信息

```bash
# 步骤1：配置主码流（流0）为4M H.265
test_encode -S 0 -H 4k
# 步骤2：配置子码流（流1）为1080p H.264
test_encode -S 1 -h 1080p
# 步骤3：加载资源配置（使步骤1、2的配置生效）
test_encode --resource-cfg /etc/amba/lua/dual_stream_cfg.lua
# 步骤4：启动这两个流
test_encode --start-multi 0~1
# 步骤5：查看流状态
test_encode --show-stream-info
```

### 场景3：性能分析与调试

```bash
# 查看系统负载和内存情况
test_encode --show-system-state
# 查看详细的DSP内存布局，分析是否有溢出
test_encode --show-dram-layout
```

### 场景4：动态调整参数（无需重启编码）

```bash
# 1. 首先启动编码
test_encode -S 0 -H 1080p --resource-cfg sensor_cfg.lua -e
# 2. 动态修改流0的码率（例如更改为2Mbps）
test_encode -S 0 --bitrate 2000000
# 3. 强制插入一个IDR帧
test_encode -S 0 --force-idr
```

### 场景5：预览与编码

```bash
# 最常见的调试命令，实时在显示器上看到摄像头画面
test_encode --resource-cfg imx327_1080p.lua --vout-cfg cv5_hdmi_1080p.lua
# 运行后按 q 键退出预览

# 预览的同时进行录像
test_encode --resource-cfg imx327_1080p.lua \
            --vout-cfg cv5_hdmi_1080p.lua \
            -e h264 -o /tmp/record.h264

# 无屏幕设备，禁用预览仅编码
test_encode --resource-cfg imx327_1080p.lua \
            --vout-cfg cv5_hdmi_1080p.lua \
            --nopreview \
            -e h264 -o /tmp/record.h264
```

### 场景6：通过 cfg-params 覆盖 Lua 配置

```bash
# 通过 --cfg-params 在命令行中直接覆盖 Lua 文件内的 VOUT 配置项
test_encode --resource-cfg imx327_1080p.lua \
            --vout-cfg cv5_hdmi_1080p.lua \
            --cfg-params "vout0: mode='1920x1080p60', video_flip_mode='v'"
```

## 3. 核心要点总结

1. **配置与执行分离**：先用 `-S`、`-h`、`-H` 等参数声明流的配置，然后通过 `--resource-cfg` 加载 Lua 文件使能硬件管道，最后用 `-e` 或 `--start-multi` 启动编码

2. **Lua 文件是核心**：绝大多数硬件相关的复杂配置（Sensor、ISP 参数、管道连接、画布分配）都在 `--resource-cfg` 指定的 Lua 文件中。命令行参数常用来覆盖或调整编码层面的参数（如码率、分辨率）

3. **多路编码逻辑**：通过 `-S` 指定不同流 ID 来配置多路。确保 Lua 配置文件中已为该流分配了相应的源（Canvas）和编码资源

4. **善用调试命令**：`--show-*` 系列命令是解决资源分配错误、性能问题的最直接手段

> 建议：初次使用时从最简单的单流命令开始，逐步增加复杂度。每次修改参数后，用 `--show-stream-info` 和 `--show-system-state` 验证配置是否生效。
